# 出缺席總表

使用者會一次給好幾份出缺席點名表(通常每份是一天,版面像:學生、座號、第1節…第8節,
節次格空白=出席,填「缺席/遲到/請假」=該節狀況)。你的工作是把它們合併成**固定格式的總表**,
讓使用者每次拿到的東西長得一樣、可以直接查詢,而且知道哪裡需要他確認。

## 流程

1. **找出所有輸入檔**:`/mnt/user-data/uploads/` 底下的 .xlsx / .csv。先 `view` 一遍,了解有幾份、版面是否一致。
2. **執行合併腳本**(版面符合上述格式時,不要自己重寫):
   ```bash
   python /mnt/skills/user/attendance-summary/scripts/build_summary.py \
     /mnt/user-data/outputs/出缺席總表.xlsx  檔案1.xlsx 檔案2.xlsx ... [--year 2026] [--date "檔名::工作表=YYYY-MM-DD"]
   ```
   腳本路徑以實際安裝位置為準(skill 資料夾下的 `scripts/build_summary.py`)。
3. **日期判斷不出來時(exit code 2)**:腳本會印出哪些檔案/工作表缺日期。**直接問使用者**,
   一次問完所有缺的,再用 `--date` 補上重跑。日期是查詢與每日統計的依據,猜錯會讓整份總表失真,所以不要猜。
   腳本判斷順序是:工作表名稱 → 工作表上方日期儲存格 → 檔名;支援 2026-11-11、2026/11/11、
   11月11日、20261111、民國 114/11/11。只有月日時年份用 `--year`(預設今年),並會在核對報告標示「年份為推測」。
4. **重算並驗證**:`python /mnt/skills/public/xlsx/scripts/recalc.py 出缺席總表.xlsx`,`total_errors` 必須為 0。
   再用腳本輸出的 `tally`(Python 端獨立統計)對照「總表」工作表的數字,不一致就先查原因。
5. **回傳**:`present_files` 交付檔案,並在回覆中給使用者看(見「回覆格式」)。

版面不符(找不到「學生/姓名」或「第N節」欄、橫向以日期為欄、一個儲存格塞多筆資料等)時,腳本會在核對報告列出
「無法辨識版面」。這時改為自己讀資料、整理成相同的「紀錄」格式,再照下面的活頁簿結構產出;
不要硬套腳本,也不要悄悄略過那份資料。

## 總表活頁簿結構(固定)

| 工作表 | 內容 |
|---|---|
| **總表** | 每位學生一列:座號、學生、紀錄天數、缺席次數、遲到次數、請假次數、全勤天數;最下方合計、統計期間、統計天數。**姓名黃底 = 整個統計期間完全沒有缺席/遲到/請假紀錄。** |
| **每日統計** | 每個日期一列:缺席人次、遲到人次、請假人次、全勤人數、紀錄人數 |
| **查詢** | 選學生、輸入日期、選節次 → 顯示該節狀態;並列出當天各節與該生全部日期累計 |
| **紀錄** | 所有天數的明細,每位學生每天一列(日期、座號、學生、第1~N節、當天狀況數);使用者之後可以接著往下新增 |
| **學生名單** | 座號與姓名,供下拉選單使用 |
| **核對報告** | 來源檔案與採用日期、需要確認的項目、狀態判讀規則 |

統計與查詢全部是公式,連到「紀錄」,所以使用者補資料或修正後會自動更新。這是刻意的:
總表是之後還會被拿來用的工具,不是一次性的截圖。

## 判讀規則(為什麼這樣算)

- 空白、「出席」→ 出席,不計。含「缺」「曠」→ 缺席;含「遲」→ 遲到;含「假」(病假、事假、公假…)→ 請假。
  無法辨識的寫法不計入任何次數,列在核對報告,讓使用者決定。
- **某天沒出現在資料裡的學生不算缺席**,只是那天沒紀錄(紀錄天數較少),會列在核對報告。
  把「沒資料」當「缺席」會冤枉學生,而且使用者可能只是漏給一份表。
- 同一天同一學生出現在多份資料:逐節合併;同一節內容衝突時保留先出現者並報告。
- 座號與姓名不一致、座號重複,只報告、不自行更正。

## 回覆格式

回傳檔案後,用簡短文字交代:

1. 一句話:合併了幾份、幾天(日期範圍)、幾位學生。
2. 一張簡表:學生 / 缺席 / 遲到 / 請假 / 全勤天數(數字取自重算後的總表),並點出黃底(全勤)名單。
3. **需要你確認的事項**:把核對報告裡的重點條列(推測的年份、無法辨識的狀態、哪天缺哪些學生的資料、座號衝突)。
   沒有異常就說沒有,不要編造疑慮。
4. 提醒可以用「查詢」頁找特定學生/日期/節次。

保持簡潔;完整細節都在檔案裡,不必在對話中重複。
